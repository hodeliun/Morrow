# Evidence — synthetic demonstration vault

## Delivered

The synthetic vault lives at `demo/vault/`; its opening instructions are in `demo/README.md`. It contains 29 Markdown pages and five local SVG assets generated by `demo/.morrow-tools/build-demo.mjs`. Names, purchases, media records, and artwork are invented for this fixture.

The vault covers the Asha RPG profile and child pages, two linked views over the same artifact table, a live resource-cost relation, entertainment status/type/rating/progress examples, and a BRL finance panel with invoices, expenses, named controls, and an installment preview.

## Automated verification

- `node demo/.morrow-tools/build-demo.mjs` generated the vault successfully.
- `npx vitest run --config demo/.morrow-tools/vitest.config.mts` passed: 1 file, 5 tests. The tests load the vault through the production parser/loader, verify no unreadable pages or diagnostics, exercise linked filtering and live relation recalculation, inspect local media/rich-cell payloads, check entertainment grouping and calculated progress, verify formula bindings and finance totals as controls change, and preview three installments totaling exactly 10,000 cents.
- `npm run typecheck` passed.
- `npx eslint demo/.morrow-tools/demo-vault.test.ts demo/.morrow-tools/build-demo.mjs` passed.

## Limits of this evidence

This is parser/loader and core-scenario evidence. No application window was launched. Visual layout, editing through the UI, fresh-row default behavior, close/reopen behavior in the app, and final integrated build remain for the principal's integration review. The installment check validates the explicit action preview plan; it does not claim that execution or disk persistence was exercised here.
